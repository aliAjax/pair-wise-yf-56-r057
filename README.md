# pair-wise-yf-56 网络安全事件响应作战室

## 源提示词摘要
值班人员接收告警，分析人员补充资产和影响范围，响应负责人批准隔离、封禁或恢复动作，法务和公关维护对外口径。系统展示实时事件时间线、子事件、审批、证据和责任人；高优先级动作双人确认，敏感内容按角色显示，并支持只读演示模式。

## 技术栈
Next.js 15 + TypeScript + App Router + shadcn/ui 本地组件 + Zustand + TanStack Query + React Hook Form + Zod + next-intl + date-fns + dnd-kit。

## 已实现闭环
- 主事件、子事件、处置动作和实时时间线。
- 子事件创建、动作审批、双人确认和执行状态流转。
- 角色权限控制、敏感内容遮蔽、只读演示模式。
- dnd-kit 调整处置优先级、TanStack Query 实时连接检查和 Zustand 持久化。

## 离线协同与冲突合并
- **操作日志（op）**：所有变更以操作为单位，按事件/动作标识（`entityId`）合并；每个操作有全局唯一 `op.id`，重试幂等，不会重复审批或重复执行。
- **权威端**：`lib/collab/server.ts` 以 localStorage 为唯一事实来源，跨标签页通过 Web Locks 串行化提交，`BroadcastChannel` 广播变更；离线时操作进入本地发件箱，恢复网络后自动合并。
- **乐观更新 + 待确认回执**：本地先应用操作，发件箱保留 `pending/failed/conflict` 状态与回执；执行失败保留回执并按指数退避自动重试，也可手动重试/放弃。
- **版本冲突**：每个实体带版本号 `v`，编辑操作携带 `baseV`；两个标签页基于旧版本修改同一动作时，后提交方收到冲突，当前版本与冲突版本同时保留（`conflicts[]`），页面展示两版内容，不静默覆盖。
- **双人审批**：隔离动作需两名**不同角色**且具备敏感可见权限的审批人；同角色重复审批幂等拒绝。
- **策略失效**：权限策略或敏感级别变化后，不满足条件的待执行动作立即置为 `invalid` 并记录时间线；已执行结果与历史时间线保留不变。

## 演示
- 权限与敏感级别面板可调整角色审批/执行/敏感可见权限、切换动作敏感级别。
- 「模拟服务端故障」：首次请求返回 500，重试即成功，用于演示回执与重试。
- 「模拟离线」：操作入队，取消后自动合并，用于演示离线续作。
